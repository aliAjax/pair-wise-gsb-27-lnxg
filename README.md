# 多承运商物流竞价台（可追溯）

- 行业：物流
- 技术栈：Vue3、Vite、TypeScript、Pinia
- 启动：`npm install && npm run dev`
- 构建：`npm run build`
- 规则引擎冒烟测试：`node_modules/.bin/esbuild scripts/smoke.ts --bundle --platform=node --format=esm --outfile=/tmp/smoke.mjs && node /tmp/smoke.mjs`

数据全部保存在浏览器 localStorage 中。

## 业务闭环

1. 录入客户、城市、实重、体积、时效、温控与发货日期。
2. 计费重 = max(实重, 体积重, 最低计费重)，体积重 = 体积 × 规则版本系数。
3. 仅「在营 + 覆盖该方向线路 + 所需资质在发货日有效 + 冷链温区满足 + 当前规则版本有费率卡」的承运商参与最低价选择。
4. 没有合格承运商时**阻止下单**，并列出：
   - 缺失/失效资质（按资质类型分组、对应承运商）；
   - 冲突线路（当前有效覆盖承运商为 0 家的线路）。
5. 确认后**冻结**：承运商快照、规则版本快照、全量竞价结果、逐项费用明细、冻结时各承运商在营状态。
6. **换价只能新建带原因的修订**（同一报价单号形成 v1→v2… 链），修订按当前数据重新竞价、重新冻结；历史版本不可改。
7. 承运商停用 / 规则归档 / 费率卡改价后，历史报价仍按快照执行；页面同时用现行数据重算并标注差异（仅审计展示，不改快照）。
8. 报价链与停用状态随记录持久化，**刷新后保持一致**。

## 分层（数据 / 规则 / 页面分离）

```
src/domain/      领域类型 + 规则引擎（纯函数，不依赖 Vue/存储）
  types.ts         数据模型
  rules.ts         计费、资质校验、竞价、阻止下单判定
  verify.ts        历史快照核对（停用/改价/归档差异）
src/data/        数据层
  seed.ts          种子数据（城市/承运商/资质/线路/规则版本/费率卡/历史报价）
  repository.ts    localStorage 仓储，只读写、不含规则
src/stores/      页面状态（Pinia，编排规则与数据）
src/components/  页面：竞价台、报价与修订链、数据管理
scripts/smoke.ts 规则引擎冒烟测试（19 项）
```

## 演示数据看点

- 「鼎力物流」普通货运资质 2026-08-31 到期，2026-09 的常温单会因资质过期落选。
- 冷冻单仅「北极冷链」合格（丰驰无冷链资质）。
- 「老牌快运」已停用：历史报价 BJ-20260410-001 仍按其冻结快照核对与执行。
- 改出发/目的城市为无人覆盖的线路（如成都-广州），可看到阻止下单与冲突线路提示。
- 数据管理中可发布新规则版本（如体积重系数 250→300）、编辑费率卡、停用/恢复承运商。
